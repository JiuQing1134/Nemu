# 23 审计修复记录（2026-11-23）

> 范围：`docs/21-audit-2026-11-23.md` 之后的全代码审计发现，以及
> FlClash 主题移植后新发现的状态/生命周期问题。
> 方式：逐项修复；每项先补回归测试或契约测试，再运行全量 JVM 测试。
> 本轮没有在手机上安装或执行冻结操作。

## 1. 安全/所有权

1. **预览模式全部解冻不再真实清理残留**：之前 `onCatalogRestoreAll` 在预览下
   仍调用 `safetyService(backend).residualUnfreeze()`，会真实 unsuspend。
   现在由 `RestoreExecutionPolicy` 统一判断，预览只显示
   “安全残留：预览不执行”。真实解冻、关机、开机恢复仍使用 `dryRun=false`。
2. **关机路径移出主线程并去重**：`ShutdownReceiver` 与 `SafetyService` 都通过
   `ShutdownSafety.runAsync` 启动 IO 协程；`ShutdownGate` 保证只有第一个接收器
   拥有本次关机，且 15 秒内顺序到达的重复广播不会重跑或覆盖结果。
   关机的开始/完成写入集中到 `ShutdownSafety`。
3. **组件状态读回不再把 null 当成功**：`ComponentRestoreState` 只接受
   0/1（默认/启用）；null、2/3/4 都视为未恢复，保留唯一基线。
4. **Unknown component 分支可达**：先识别 `Unknown component`，再走通用成功分支；
   清理 root marker 失败会报告而不是静默吞掉。
5. **旧组件可恢复**：`OwnedComponentCatalog` 合并当前登记组件与仍拥有基线的
   已移除/改名组件；用户恢复、残留恢复、关机脚本都使用合并结果。
6. **组件选择器不再立即改手机**：取消勾选只保存选择；下一次“应用”时先恢复
   已取消勾选且 Nemu 仍拥有的组件，再应用新选择。
7. **SUSPEND/HIDE 重新应用**：Nemu 自己已暂停/隐藏的目标可幂等重试；
   他人暂停/隐藏仍拒绝接管。SUSPEND 失败时只有读回明确为 false 才丢所有权。
8. **DISABLE_USER 读回 null 失败关闭**：只有读回 false 才算停用成功。
9. **号码识别 HIDE 模式**：`NumberIdentityMode` 增加 HIDE 并双向映射，
   不再把 HIDE 写成 OFF；SUSPEND/DISABLE_USER/HIDE/OFF 全部可往返。
10. **isApplied 包含全部所有权证据**：hidden 所有权、disable-user 原始基线、
    组件基线（owned 或 original 任一）都算已应用。
11. **自定义目标删除**：只要存在持久所有权或实际冻结状态就拒绝删除。
12. **限制后台/待机需要 Root**：无 Root 时预设直接显示“需要 Root”并置灰；
    服务层在缺少 root marker backend 时不写 AppOps/standby。
13. **组件基线持久化**：先同步写入 exact original state + owned 标记；
    任一写入失败会回滚另一半，并在 `pm disable` 前中止。
14. **disable-user/开机尝试持久化**：原始启用基线、applied 标记和
    `recordAttempt` 写入失败时不再继续执行；开机冻结会重试/失败关闭。

## 2. 启动/恢复/生命周期

1. **旋转与返回**：MainActivity 对旋转/尺寸变化保留组合；有长操作时拦截返回，
   避免旋转或误触 Back 取消冻结/解冻。
2. **Direct Boot**：`NemuApplication.reloadAfterUnlock` 在 USER_UNLOCKED/
   BOOT_COMPLETED/MY_PACKAGE_REPLACED 重新加载自定义目标和日志开关。
3. **BootWorker 判断顺序**：等待 Root/Shizuku 之后才重新判断“本次开机已冻结”，
   避免等待期间的新冻结被残留解冻撤销。
4. **暂时性启动失败不消耗开机机会**：无后端、系统未启动完成、状态未知会在
   3 次内重试，期间不写开机尝试/结果；真正放弃时才记录失败。
5. **救援状态三态**：`BootGuard.rescueState` 区分有标记/无标记/不可读；
   不可读时开机冻结重试或失败关闭，不再假装 false 继续执行。
6. **开机计划刷新**：目标开关、预设、组件选择、自定义目标增删后立即
   `ensureScheduled`；纯观察预设会关闭开机计划，避免“计划开关开着但不执行”。
7. **关机脚本与安全策略一致**：关机不再 `pm enable` disable-user；
   只有显式解冻会恢复。`docs/13` 已同步修正。
8. **重复恢复标记清理**：恢复前验证组件/隐藏状态；marker 清理失败会保留基线
   并报告，不提前删除唯一恢复记录。

## 3. UI/交互

1. **批量选择作用域**：搜索/分类切换会清理不可见选择；批量全选、计数、
   应用都只作用于当前可见且可执行目标；观察/不可用目标整行不可选。
2. **恢复页搜索**：同样清理不可见选择，确认按钮使用可见选择。
3. **检测页**：SUSPEND/DISABLE/COMPONENT/HIDE/RESTRICT 使用各自实际状态文案
   （不再把所有模式都写成“暂停”）；切换分类回到列表顶部。
4. **设置二级页**：打开/返回二级页回到顶部，不再复用旧滚动位置。
5. **首帧窗口**：浅色窗口/状态栏/导航栏从旧 `#F2F7FA` 改为 FlClash page
   `#EFEDF0`，消除启动闪色。
6. **批量复选框**：增加 Checkbox 语义/操作标签；开关/选择控件不再出现方形波纹。
7. **默认安全**：新安装 `dry_run` 默认 true；已有用户保留原设置。

## 4. 可观测性/构建

1. **日志异步写**：生产日志由单线程守护 writer 串行写入，UI 不再同步写文件；
   读取/清空/文件列表前有 flush 屏障。测试入口仍可同步写。
2. **lint 错误清零**：`QUERY_ALL_PACKAGES` 为全应用选择器所需，显式
   `tools:ignore`；`lintDebug` 现在 0 errors。
3. **测试**：416 个 JVM 测试 / 69 个测试类 / 0 失败。
4. **构建**：debug、release、arm64-v8a、x86_64 均成功；lint 0 errors。
