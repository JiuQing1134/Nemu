## 3. 发现并修复

### 3.1 应用页权限提示自相矛盾

- 现象：顶部 chip 为 `Shizuku（Root 启动）`、授权卡写“Shizuku 可执行冻结与解冻”，
  应用页却写 `无 Root：仅支持暂停和观察。`
- 判断：`DashboardState.rootAvailable` 表示 **Root 后端**（组件/停用/隐藏的救援
  marker 需要它），不等于“完全不能冻结”。旧文案把所有 Shizuku 场景都说成仅观察。
- 修复：改为按 `PrivilegeOverview.canFreeze` 区分：
  - `Shizuku：可暂停/冻结；组件/停用/隐藏需 Root。`
  - 无可用权限时：`无可用权限：仅支持观察。`
  - 快照未到时：`正在检查权限…`
- 验证：修复后应用页显示新文案，冻结 chip 仍可选，组件/停用/隐藏仍按需要 Root 置灰。

### 3.2 开机页不显示总开关状态

- 现象：概览已显示“开机 已关闭”，开机与恢复页仍只写“开机 120 秒后…”，
  用户看不出本次开机不会执行。
- 修复：开机卡片增加 `总开关：已开启/已关闭` 行；副标题改为
  `开机 120 秒后执行；总开关在概览页。`
- 验证：修复后显示 `总开关 已关闭`、`计划 无；开机不执行`。

### 3.3 刷新授权后 Root 门控不更新

- 判断：`refreshPrivilege()` 只更新 `privilegeOverview`，没有同步
  `cotaRootAvailable`（`DashboardState.rootAvailable` 的来源）。用户刚在
  KSU 里授权 Root 后点“刷新状态”，顶部会显示 Root 已授权，但组件/停用/隐藏
  和 COTA 仍按“无 Root”置灰，直到下次其他路径重新探测。
- 修复：抽出 `loadPrivilegeOverview()`，同时更新 `privilegeOverview`、
  `cotaRootAvailable` 和 `backendStatus`；启动、请求授权、刷新状态三条路径
  统一走它。
- 验证：修复后 Root 授权可用时应用页组件 chip 解锁；本机随后已实际出现
  `Root` 授权，组件不再显示“需要 Root”。

### 3.4 预览模式仍写“应用立即执行”

- 现象：打开预览后，应用页仍显示“应用立即执行”，与“点应用不修改手机”矛盾。
- 修复：按 `state.dryRun` 切换为
  `点应用只记录预览；开机按计划重跑。无目标时完全待机。`
- 验证：预览下显示新文案，实际执行模式保留原文案。

### 3.5 结果行双冒号

- 现象：UI 前缀“上次结果：”叠加 `runSummary()` 的“成功：尝试…”，显示成
  “上次结果：成功：尝试 1…”。
- 修复：`runSummary()` 改为“成功，尝试…”/“有失败，尝试…”。
- 验证：最终构建预览应用后显示
  `上次结果：成功，尝试 1，成功 1，失败 0`。

## 12. 审计问题修复（2026-11-23）

### P1

1. **bootloop 守卫**：关机解冻开始前用同一事务写
   `last_shutdown_result = 进行中` + 时间戳；完成后才写结果。进程被杀不会
   留下“昨天的成功 + 新时间戳”。
2. **退役策略恢复**：新增 `FreezeStrategyPlanner.restoreOnly`，恢复不再走
   `validate()` 的 `require`；启动迁移加 try/catch，异常只记录不会中断。
3. **部分解冻计划**：先记录 `previouslyOwned`，恢复后逐目标检查
   `isApplied/ownsHidden`；成功项关闭计划，失败项保留。
4. **not found 误判**：只有 `exitCode >= 0` 且精确匹配
   `Unknown (target )?package` 才算已解决；`su not found` 的 `-1` 记失败。
5. **策略切换 UX**：已生效目标的其他策略 chip 直接禁用，就地显示
   “已生效；切换策略前先在恢复页解冻”。
6. **debug 构建**：新增 `release`（`isDebuggable=false`，不含 Compose
   tooling）；本地测试用 debug keystore 签名，已安装 release APK。
   MainActivity 仍导出（桌面启动器要求），保留来源/root 限流风险说明。
7. **COTA 备份信任**：备份根改为 app 私有
   `filesDir/cota-backup`；manifest 先 `stat` 限 64 KiB；拒绝 setuid/setgid
   mode；恢复前检查源文件是普通文件且非 symlink。

### P2

- HIDE 回滚/ALREADY_VISIBLE/成功恢复统一走 `clearHiddenOwnership`：先清 root
  marker，再清 in-app baseline；marker 清失败计入失败。
- 组件基线与 marker 从 `FreezeStrategyController` 移出，`TargetFreezeService`
  在读回确认组件已启用后才清除。
- 预览模式不再把一次性策略迁移标记完成；迁移异常被捕获。
- `BOOT_COUNT` 不可用时改用 `/proc/sys/kernel/random/boot_id` 的 8 位十六进制；
  仍不可用返回 -1，策略/调度器对 -1 失败开放（不当作同一 boot）。
- 安全解冻只处理 Nemu 拥有（`isApplied/ownsHidden`）的暂停目标；
  `boot_guard.sh` 正常开机不再 `unsuspend_all`，rescue 路径保留。
- 日志“清空”同时清 `ActionLog` 内存；恢复计数改用
  `hasFrozenState || applied`；聚焦包时隐藏分类/搜索；选中 0 项分类保持可见；
  自定义添加过滤已在 Nemu 的应用。
- Switch 增加 `contentDescription`；首卡开关去掉 0.78 缩放；检测卡只让标题行
  可点，按钮移出；恢复行整行可点。
- 删除未引用的 `NemuTheme` shim；`NemuTheme` 注释改为六套配色；
  “五套”注释改为六套；`swatchColor` 实际使用；删除不可达的
  `DetectionPage` fallback / `DetectionUiState`。
- 应用页工具栏压成一行：`开机计划 N / 批量 / 刷新 / 添加`；计划为 0 时
  不显示计划 chip；批量模式不再单独占行。
