# 中文文案与排版规范（2026-11-25）

本规范是 Nemu 界面中文的统一口径。新增文案先查术语表，再按“状态 + 影响 + 下一步”写。

## 1. 术语表

| 概念 | 固定写法 | 不要写 |

| 开机计划 | 开机计划 | 开机冻结计划、自动冻结计划、冻结计划 |
| 开机计划总开关 | 开机计划总开关 | 开机自动冻结总开关（只保留“开机自动冻结”作为功能名） |

## 2. 状态词

- 结果：成功、失败、已跳过、未执行、已记录。
- 读取：已读取、未读取、读取失败。
- 计划层：已加入计划、未加入计划、已加入 · 未生效、与计划不符。
- 实际层：已冻结、已暂停、已停用、已隐藏、已限制、仅观察、他人暂停、仍有进程、组件已停用。
- 不使用“正常”概括未验证状态；启动安全用“未见异常”，守卫用“未触发”。

## 3. 句子模板

- 状态：`现状 + 是否执行 + 下一步`。
  - 例：`开机计划总开关已关闭，本次不会执行。`
- 影响：`动作 + 立即后果 + 数据/入口是否保留`。
  - 例：`停用整个应用，桌面入口消失；数据保留。`
- 风险：`高风险：若……可能……，请确认后再继续。`
- 错误：`操作失败 + 用户下一步`；退出码、shell 输出、SHA-256、manifest 只进 ActionLog。
- 预览：`预览：只记录操作，不会真正执行。`

## 4. 排版层级

- 页面标题：20–24sp，semibold；一屏只出现一次。
- 卡片标题：15–17sp，semibold；一卡只说一件事。
- 正文：13sp / 18sp 行高；卡片正文最多 2 行，长解释放弹窗。
- 状态 chip：11–12sp，2–5 个汉字；同一状态不在标题、副标题、chip、正文重复三遍。
- 按钮：动词开头，常规 2–6 个汉字；主按钮一个卡片只放一个。
- 数字与量词：`3 个`、`120 秒`、`3 项`；聚合计数统一 `实际生效 N / M`。
- 中文标点：`，。；：`、引号 `“”`、省略号 `…`；英文术语两侧留空格（`Root / Shizuku`），中文复合名不加空格（`冻结/解冻`）。

## 5. 当前已落地的结构调整

- 冻结/解冻页：批量按钮改“执行策略 N 个”，确认键“确认执行”；单卡按钮“立即执行/重新执行”。
- 解冻页：“解冻并移出开机计划”“本次解冻”；“关闭计划”“临时解冻”已移除。
- 开机卡片：统一“开机计划”“开机计划总开关”“N 秒后执行”。
- 检测页：总览计数改“实际生效”；“他人暂停”“组件已停用”“未见异常/未触发”等状态统一。
- COTA：时间标为“修改时间”；错误不再直接展示退出码和英文 shell 输出；大小列改为最小宽度，避免大字体截断。
- 首页统计：`3 个 · 已生效` / `3 个 · 计划中`，不再出现“3 计划中”。

## 6. 后续可做的结构优化

1. 开机卡仍有副标题、chip、正文重复状态；可删正文重复行，只保留跳过原因。
2. 检测冻结行同时显示状态 chip 和摘要行；可只在异常时显示 chip，正常行只留摘要。
3. 设置根页摘要控制在 20 字内；更长的原因放到二级页。
4. 目标卡片的高风险说明已按更新/推送/支付/温控/云控分流；后续新增目标必须补对应句。
